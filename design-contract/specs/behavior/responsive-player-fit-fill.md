# WEB-PLAYER-FIT-001 — Picture Fit / Fill

Status: proposed for the responsive website player. Source: owner request, 2026-10-02. Applies to phone and desktop website viewing, including the same responsive UI in a desktop window. The TV remote player and native Android player retain their current presentation rules.

The video starts in **Fit**. Fit shows the whole picture at its native aspect ratio, with letterboxing where the display shape differs. The player tools include a visible 44 px **Fit** button immediately before Fullscreen. Activating it changes the button to **Fill** and makes the picture cover the player viewport by cropping equal excess around its center. Fill never distorts the aspect ratio. Activating it again restores Fit. This applies to the HTML video and decoded canvas surfaces, in windowed and fullscreen playback, including portrait and landscape phones. Captions and controls remain over the viewport and are never cropped with the picture.

The button is keyboard and touch accessible. Its accessible name is **Fill video** or **Fit video**, describing the available action; its pressed state indicates Fill. One click, tap, Enter, or Space toggles once. Holding or repeating is ordinary browser button behavior with no extra shortcut. Focus stays on the button after activation. Hiding/showing the controls, pausing, seeking, changing tracks or quality, swapping a source for the same title, decoder fallback, resizing, and entering/leaving fullscreen retain the chosen mode. Entering a different title or episode, or leaving the player, resets it to Fit. The choice is local presentation state and causes no preparation, backend call, history entry, or playback session change.

If the video has not provided dimensions, the selected button state remains visible and the mode takes effect when frames arrive. On an audio-only stream the button still toggles harmlessly; no video surface is altered. There is no loading or error state for a CSS presentation change. Returning from an error to the same player retains the mode; leaving it resets Fit.

Acceptance: in a 390 px portrait viewport, a 16:9 frame Fits inside the player with top/bottom bars, then Fills width and height with symmetric horizontal crop; the five visible phone tool buttons remain reachable. At desktop width a tall frame alternates between full picture and centered crop. The HTML video and MediaBunny canvas both obey the same mode. Toggle during pause and fullscreen without a new media request; source replacement for the same item keeps Fill; moving to the next episode or leaving and re-entering starts Fit. Keyboard focus stays on the button, and the accessible action/pressed state follow the selected mode. Browser tests establish layout and state; physical device display behavior remains unverified until device execution.

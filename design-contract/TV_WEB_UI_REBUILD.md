# Shared Tizen and Vizio presentation replacement

Status: shared presentation replacement implemented on 2026-09-13; browser validation passed, with matched-state visual and physical-device qualification still partial. This applies the owner's Android Roku-matching rebuild direction to the shared React TV frontend. Historical browser/packaging passes in [the candidate checkpoint](TV_CANDIDATE_2026_09_12.md) do not qualify the replacement. Tracking: [design #4](https://github.com/viptv-org/design/issues/4) and [tv-web #2](https://github.com/viptv-org/tv-web/issues/2).

Replace the shared presentation across every screen with the frozen Roku composition, including the runtime extraction corrections already recorded in the visual specifications. Tizen and Vizio consume the same screen components, styles, assets and controller semantics; AVPlay and HTML-media differences remain behind their platform adapters. Preserve authenticated accounts, pairing, profile identity, provider/addon configuration, history, source selection and direct-first playback contracts. This work does not redesign or deploy Roku.

## Contract and geometry ownership

Read [VISUAL_SYSTEM.md](specs/visual/VISUAL_SYSTEM.md), [SCREENS.md](specs/visual/SCREENS.md), [STATES_AND_MOTION.md](specs/visual/STATES_AND_MOTION.md) and [roku-ux-contract.md](specs/behavior/roku-ux-contract.md) together. These own exact coordinates, copy, timing, press/release/repeat/hold actions and error recovery. This document is the rebuild acceptance index, not a second set of numeric tokens. [TV_IMPLEMENTATION.md](TV_IMPLEMENTATION.md) owns the keyboard, remote and host-exit equivalents; [PLAYBACK_CAPABILITIES.md](PLAYBACK_CAPABILITIES.md) owns adapter capability policy.

Use one uniformly scaled canonical TV canvas and the design-owned packaged assets. In particular, Home has a fixed backdrop and an independently clipped shelf viewport; lower shelves hide the hero and its actions. Movie details place actions after the measured synopsis. Series show one visible episode row with artwork-only focus; Settings uses its description column; Search keeps keyboard and results as separate focus regions; Guide clips programme cells within its timeline. All precise dimensions and dynamic overrides remain in SCREENS.md. Use the declared text hierarchy, artwork fallbacks, rounded alpha clipping, monochrome focus inversion and gradient assets. Preserve metadata fields needed for artwork, synopsis, credits and progress.

A discrepancy with actual frozen Roku dynamic layout is an extraction correction: identify the exact source revision and state, correct its owning visual/behavior section in design first, then sync both web TV targets. A new interaction or deliberate platform exception is proposed separately. Neither a passing Android screen nor an old TV-web fixture overrides the normative contract.

## Retained source-filter adaptation

The existing shared TV-web frontend exposes a separate `Quality: {selection}` filter alongside `Provider: {selection}`. This rebuild retains that keyboard/pointer/remote-accessible control rather than silently removing existing filtering. It is an implementation adaptation, not a frozen Roku control or an owner-approved visual-parity exception. Track its remaining difference explicitly in TVW-09 evidence.

The provider keeps the canonical source-filter position. Quality occupies x=804, y=166, 256×48 in the source-help region; status stays x=384, y=178 with its text bounded before Quality. Full source details remain available through the source action menu/hold/right-click. Both filters open choice dialogs, preserve the other selection, return to their triggering control on dismissal and never start playback. Empty combined results retain both filters and restore provider focus; changing filters must not discard the saved playback position or source identity. Verify this behavior for both shared configurations. The Roku source-picker geometry in SCREENS.md remains unchanged.

## Delivery checkpoint — 2026-09-13

The shared React presentation was replaced across gateways, rail/Home, discovery, detail/episodes, sources, Search, Guide, Settings and player chrome. The app imports committed design documents and artwork with a hashed lock and immutable pin; build checks detect modified imported files, and explicit freshness checks compare to a selected design checkout. A PR template records screen IDs and evidence.

The completed local batch passed 43 unit tests, TypeScript/production build, both candidate packages and 49 browser scenarios with 33 explicitly platform-skipped cases. Both configurations passed fixed-canvas/1080p scaling and real series-history/episode-focus scenarios. Whole-frame SSIM comparisons against the private frozen Roku references measured Settings 0.955989 and blank Search 0.923059, normalized to 1280×720 without masking/alignment changes. The browser used a different profile avatar and browser system font; Search help describes the available platform input. These are scoped measurements, not a score for every screen.

The blank Search state now preserves the native placeholder, empty result region, symbol keys and focus outline. The old standalone Search scope chip was removed; catalog-specific search remains in Discover. Source quality retains the adaptation documented above. Episode metadata/history merging preserves thumbnails, watched state, resume positions and source identity. More info remains fully readable in the scrollable text presentation.

The implementation's [TESTING.md](https://github.com/viptv-org/tv-web/blob/main/TESTING.md) and [parity matrix](https://github.com/viptv-org/tv-web/blob/main/tests/PARITY_MATRIX.md) record the published implementation/CI revision and outstanding scenarios. Home, detail, Guide, profiles, source and playback states still need matched real-content comparisons; browser fixture inspection is not physical TV evidence. Tizen signing/AVPlay and physical Vizio remote/decoder qualification remain unverified. Roku runtime and owner data were unchanged. Figma-first remains the proposed authoring workflow in DESIGN_SYNC.md, not an installed or required service.

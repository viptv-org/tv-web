# Responsive guide research — 2026-09-14

Android's official adaptive-navigation guidance recommends persistent leading navigation for expanded windows, choosing the navigation surface according to available width and item count. It also says resizing should preserve the current destination and state. The VIPTV application of that guidance is a category sidebar on desktop and a labeled native category picker on compact screens, backed by the same selected filter and data. This is a product adaptation, not a claim that Android prescribes an EPG. [Android Developers](https://developer.android.com/develop/ui/views/layout/build-responsive-navigation)

Apple's scroll-view guidance describes visual separation between fixed controls and scrolling content. Our guide uses a bounded native scrolling region, a sticky channel column and a sticky time header with opaque backgrounds and borders, so both axes retain their context. The native browser scrollbars and a concise instruction make the additional schedule discoverable. Apple’s web documentation required JavaScript for its full body during this review; the indexed official excerpt supports the separation principle, not the exact EPG measurements. [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/scroll-views)

Implementation choices: a six-hour schedule window with half-hour markers, a forty-channel API page that scrolls vertically instead of replacing five visible rows, and page controls only at the existing API boundary. Channel identity, actual schedule/gap cells, current-versus-future activation and server filters stay intact. The existing three-worker guide fetching limit and forty-entry cache remain bounded. These are VIPTV decisions inferred from the task and current API; they are not new provider capabilities.
